# Telegram Import

Плагин превращает архив Telegram (экспорт в JSON) в заметки Obsidian одной командой:

1. копирует файлы архива (фото, видео, документы) в хранилище;
2. из `result.json` собирает заметки с шапкой (дата, источник, теги) и разложенные по папкам `notes/год/год-месяц-Месяц`;
3. расставляет ссылки `Back` / `Next` между заметками.

Работает на десктопе и на телефоне или планшете (см. раздел «Мобильные устройства»). Python не нужен. Источником может быть папка экспорта или ZIP-архив (на десктопе в том числе больше 4 ГБ).

## Установка

Скопируйте папку `telegram-import` целиком в `<хранилище>/.obsidian/plugins/`. Внутри должны быть:

- `main.js` (небольшой загрузчик)
- `src/` (готовые модули плагина, собирать ничего не нужно)
- `manifest.json`
- `styles.css` (оформление окна плагина)
- `README.md` (чтобы инструкция открывалась в настройках)

Затем включите плагин в **Настройки → Сторонние плагины**.

## Как пользоваться

1. В Telegram Desktop: **Настройки → Продвинутые → Экспорт данных Telegram**, формат **JSON**, нужные чат или канал. Получится папка с `result.json` (или ZIP, если вы упаковали её).
2. Откройте окно плагина: иконка с самолётиком в боковой панели или команда «Открыть панель импорта Telegram».
3. На вкладке **«Новый импорт»** выберите «Папка с экспортом» или «ZIP-архив», перетащите источник в рамку или нажмите на неё (можно вписать путь). Плагин просканирует архив и покажет: число сообщений, фото, видео, голосовых, файлов, веб-ссылок, нужное место и название чата.
4. Включите или выключите правила преобразования и нажмите **«Запустить полный импорт»**.

Окно состоит из четырёх вкладок:

| Вкладка | Что на ней |
|---|---|
| Новый импорт | Источник, правила, результаты сканирования, общий прогресс (процент, остаток времени, скорость, ошибки), этапы, журнал, структура папок, кнопки «Приостановить» и «Отмена» |
| Конфликты записей | Сравнение заметок с одинаковыми названиями в три колонки (см. ниже) |
| История и инфографика | Итоги по всем запускам, активность по месяцам, типы контента, чаты в хранилище, журнал сессий с логами |
| Настройки плагина | Все настройки и эта инструкция |

Значок луны в шапке переключает тему: как в Obsidian, тёмная, светлая.

Окно открывается во вкладке на всю рабочую область: боковые панели сворачиваются и возвращаются при закрытии окна (настройка «Открывать на всю рабочую область»). Кнопка со стрелками в шапке включает настоящий полноэкранный режим, Esc выходит из него.

ZIP распаковывается во временную папку системы и удаляется после импорта, так что на диске на время импорта нужно место под распакованный архив. «Приостановить» останавливает запуск новых операций, уже начатые завершаются. «Остановить» прерывает импорт, сделанное сохраняется.

Если в настройках выключить «Подтверждать источник в окне импорта», команда «Импорт из Telegram» сразу запускает импорт с сохранённым источником.

### Команды

| Команда | Что делает |
|---|---|
| Открыть панель импорта Telegram | Вкладка «Новый импорт» |
| История импортов Telegram и инфографика | Вкладка «История и инфографика» |
| Импорт из Telegram | Открывает окно; при выключенном подтверждении источника сразу запускает импорт |
| Только пересчитать ссылки Back/Next | Только третий шаг, по папке из настроек, без открытия окна. По окончании показывает уведомление «обновлено N из M» |
| Разобрать конфликты слияния (сравнение side by side) | Вкладка «Конфликты записей» |

## Мобильные устройства

Плагин работает в Obsidian для iOS и Android. Отличия от десктопа:

- **Источник.** Системного выбора папки и перетаскивания нет. Есть два способа:
  1. **ZIP из «Файлов»:** на вкладке «Новый импорт» откройте «ZIP-архив» и нажмите на рамку. Архив читается прямо из выбранного места, копировать его в хранилище не нужно. Запомнить такой источник нельзя: при следующем импорте выберите файл снова.
  2. **Папка или ZIP внутри хранилища:** скопируйте экспорт Telegram в хранилище (например, через «Файлы» или синхронизацию) и введите путь от корня хранилища, например `inbox/ChatExport`. Подсказки берутся из папок хранилища.
- **Память и место.** ZIP из хранилища на телефоне читается в память целиком, ZIP из «Файлов» читается кусками. `result.json` разбирается целиком, поэтому очень большие чаты (сотни мегабайт текста) могут не поместиться в память телефона. При распаковке ZIP во временную папку внутри папки плагина нужно место под распакованный архив, папка удаляется после импорта. Для больших архивов надёжнее десктоп.
- **Сжатие.** Для ZIP используется встроенная в систему распаковка (iOS 16.4+, Android System WebView 80+). Если её нет, плагин сообщит об этом: распакуйте архив на компьютере.
- **Даты файлов.** Скопированные медиафайлы получают дату копирования, а не исходную: хранилище не позволяет её менять.
- **Окно.** Оформление подстраивается под узкий экран. Полноэкранный режим, сворачивание боковых панелей и строка состояния недоступны.
- Всё остальное (слияние, экран конфликтов, история, команды) работает так же. Команду «Только пересчитать ссылки Back/Next» удобно вызвать из палитры команд.

## Настройки

Те же настройки есть на вкладке «Настройки плагина» окна и в **Настройки → Telegram Import**.

| Настройка | Назначение |
|---|---|
| Папка или ZIP с экспортом Telegram | Где лежит `result.json` (или ZIP с ним). Меняется и в окне «Новый импорт», запоминается после импорта |
| Подтверждать источник в окне импорта | Включено по умолчанию. Выключено: команда «Импорт из Telegram» сразу запускает импорт |
| Папка назначения в хранилище | Куда попадают заметки (`notes/год/месяц/`) и файлы архива (`photos/` и т. д.). По умолчанию `Telegram`. **Пусто: прямо в корень хранилища**, то есть заметки окажутся в `notes/`. Поле с подсказками: папки берутся из хранилища. Существующие файлы не перезаписываются |
| Папка для пересчёта ссылок | Все `.md` внутри (включая вложенные) выстраиваются в цепочку Back/Next по порядку имён. Пусто: `<папка назначения>/notes` (при пустой папке назначения это `notes`). Поле с подсказками |
| Узнавать переименованные медиа по дате в имени | Включено по умолчанию. Файл Telegram `photo_1904@03-10-2026_09-46-36.jpg` и тот же файл, переименованный плагином упорядочивания галереи (например, Media Organizer) в `2026-10-03_09-46-36_001.webp`, считаются одним: ссылки на них в тексте не различие, и файл не копируется повторно, даже если лежит в другой папке хранилища. После переключения история сверок сбрасывается |
| Атрибут с датой | Имя YAML-атрибута с датой поста. По умолчанию `Date`. У существующих заметок при пересчёте ссылок прежнее имя `Date` заменяется настроенным |
| Атрибут со ссылкой назад / вперёд | Имена YAML-атрибутов, в которые пересчёт пишет ссылки на соседние заметки. По умолчанию `Back` и `Next`. Старые `Back`, `Next` и `Prev` при пересчёте заменяются настроенными именами. Имена не должны совпадать, двоеточие и пробелы заменяются |
| Папка для конфликтов | `merge_conflicts` по умолчанию: версии из Telegram и отчёт `Отчёт о конфликтах.md`. Поле с подсказками |
| Преобразовывать теги | Включено: хэштеги становятся тегами заметки и убираются из текста. Выключено: остаются в тексте |
| Копировать медиафайлы | Включено по умолчанию. Выключено: импортируются только заметки |
| Беречь ручные правки | Включено по умолчанию, см. раздел ниже. Выключено: заметка при любом отличии перезаписывается версией из Telegram, без экрана сравнения |
| Показывать и ваши правки на сравнении | Включено по умолчанию: заметка, где вы поменяли текст (а в Telegram он прежний), один раз попадает на экран сравнения. Выключено: ваша версия молча сохраняется |
| Файлы с тем же именем, но другим расширением | Что делать, если в папке хранилища уже есть `img_001.webp`, а в архиве `img_001.png`. «Пропускать, если вид тот же» (по умолчанию): изображения, видео и аудио считаются одним файлом внутри своего вида (список ниже). «Пропускать при любом расширении»: `report.pdf` и `report.docx` тоже один файл. «Копировать»: сравнивается точное имя с расширением. Ссылки на такие файлы в тексте сравниваются по тому же правилу. После переключения история сверок сбрасывается |
| Игнорировать атрибуты | Список YAML-атрибутов (с подсказками из ваших заметок), которые плагин не добавляет в уже существующие заметки при обновлении и слиянии, например `tags` |
| Открывать конфликты после импорта | Включено по умолчанию |
| Проверять каждую заметку на диске | Выключено по умолчанию: заметки и ссылки, не менявшиеся с прошлого импорта (по дате и размеру файла), пропускаются без чтения, и повторный импорт идёт быстрее. Включите, если файлы правили программы, не обновляющие дату изменения |
| Пересчитывать все файлы | Включено по умолчанию. Выключено: файлы, где уже есть Back/Next, пропускаются, и при слиянии со старыми заметками цепочка может остаться неверной |
| Порог склейки, секунд | Сообщения, идущие подряд с меньшим интервалом, объединяются в один пост. `0`: не склеивать. По умолчанию 120 |
| Формат даты в шапке | Пусто: «7 сентября 2026, 09:41». Иначе строка вида `%d.%m.%Y %H:%M`. Поддерживаются `%d %m %Y %y %H %M %S %B %b` |
| Ключ Яндекс Static Maps | Нужен для превью-картинок локаций. Без ключа вместо картинки будет ссылка. Хранится в `data.json` плагина |
| Открывать на всю рабочую область | Боковые панели сворачиваются, пока открыто окно плагина |
| Тема окна импорта | Как в Obsidian, тёмная или светлая |

Папки назначения и пересчёта должны находиться внутри хранилища.

### Порядок атрибутов в шапке

Шапка всегда пишется в строгом порядке: дата (`Date`), ссылка назад (`Back`), ссылка вперёд (`Next`), `tags`, затем все остальные атрибуты в прежнем порядке (например, `Источник` и ваши ключи). Так собираются новые заметки, и так же пересчёт ссылок расставляет атрибуты в существующих (при включённом «Пересчитывать все файлы»). Имена даты, `Back` и `Next` берутся из настроек.

## Ручные правки и слияние

Если вы правили импортированную заметку, а потом импортируете архив снова, плагин не затирает ваши правки.

**Сравнивается только текст заметки**, то есть всё, что идёт после шапки.

- **Атрибуты** (`Date`, `tags`, `Источник`, `Back`, `Next` и ваши ключи вроде `rating`) в сравнении не участвуют. Правка одних атрибутов не считается изменением заметки, а при обновлении текста существующие значения остаются как есть. Из Telegram добавляются только новые ключи, которых у вас нет, кроме перечисленных в настройке «Игнорировать атрибуты». В новые заметки пишутся все. Ссылки Back/Next всегда расставляет пересчёт.
- **«Невидимые» отличия** не считаются различием: переводы строк (`\n` и `\r\n`), пробелы в конце строк, лишние пустые строки, неразрывные пробелы и символы нулевой ширины, разная форма записи одних и тех же букв в Юникоде, пустые строки цитат (одиночный `>`).

Одинаковыми считаются и ссылки на один и тот же медиафайл, записанные по-разному (при включённом «Узнавать переименованные медиа по дате в имени» совпадают ещё и ссылки `![](photo_1904@03-10-2026_09-46-36.jpg)` и `![](2026-10-03_09-46-36_001.webp)`): `![](photo_1904@….jpg)` и `![[photo_1905@….webp]]` не отличаются. При сравнении не учитываются запись ссылки (`![]()` или `![[]]`), папка, формат файла (`jpg`, `webp`, `png`…; если не выбрано «Копировать») и сквозной номер перед `@`: он меняется при каждом новом экспорте, потому что нумеруются все файлы экспорта. Ссылки на другой файл (например, с другой датой в имени) считаются различием, как и обычные ссылки `[[…]]`.

| Ситуация | Что произойдёт |
|---|---|
| Текст совпадает | Без изменений |
| Вы правили текст, в Telegram не менялось | Заметка один раз попадает на вкладку «Конфликты записей» (причина «Вы изменили текст»), по умолчанию выбрана ваша версия. После вашего решения она больше не беспокоит, пока вы снова не измените текст. Отключается настройкой «Показывать и ваши правки на сравнении»: тогда ваша версия молча остаётся |
| Вы не правили текст, в Telegram изменилось | Текст обновляется из Telegram, ваши атрибуты сохраняются |
| Правили и вы, и в Telegram, в разных местах | Изменения объединяются автоматически |
| Правили и вы, и в Telegram, в одном месте | Заметка попадает на экран сравнения, пока вы не выберете вариант |
| Нет записи о прошлом импорте (например, удалили `import-index.json`) | Если тексты отличаются, заметка попадает на экран сравнения |

### Что плагин хранит между импортами

В папке плагина лежит немного данных:

- `import-index.json`: короткий отпечаток текста каждой заметки на момент прошлого импорта, а также дата и размер файла для быстрой проверки. Сами заметки он не копирует.
- `import-history.json`: история запусков для окна плагина (до 120 записей, с журналом каждой сессии).
- `review-queue.json`: очередь заметок на сравнении.
- `originals/`: версия из Telegram **только для тех заметок, текст которых вы изменили** (она нужна, чтобы позже объединить ваши правки с правками в Telegram). Для заметок, совпадающих с Telegram, копий нет. Когда текст снова совпадает с Telegram, копия удаляется.

Если правка текста и изменение в Telegram произошли между двумя импортами, и плагин не успел сохранить оригинал, он не может объединить текст автоматически. Такая заметка попадает на экран сравнения.

### Конфликты записей: сравнение в три колонки

Если заметка с таким именем уже есть в хранилище, а текст в ней отличается от версии из Telegram (вы правили его, правили оба, или записи о прошлом импорте нет), она попадает на сравнение. Если содержимое одинаковое (сравнивается только текст, без атрибутов), конфликта нет, заметка не трогается.

В конце импорта окно само переключается на вкладку «Конфликты записей» (это можно отключить в настройках). Вверху: число конфликтов, «Заметка 2 из 5», точки прогресса, кнопки «Предыдущий» и «Следующий», «Применить ко всем оставшимся» (применяет рекомендуемый вариант ко всем, с подтверждением вторым нажатием).

Три колонки:

| Колонка | Что в ней |
|---|---|
| Текущая заметка в Obsidian | Ваша версия: файл, дата изменения, хеш текста. Кнопка «Использовать текущую» оставляет всё своё |
| Совмещённый вариант (рекомендуется) | Результат по вашему выбору для каждого блока; красная полоса слева у строк из вашей версии, бирюзовая у строк из Telegram. Кнопка «Использовать совмещённую» записывает его в заметку |
| Новая версия из Telegram | Версия из Telegram. Кнопка «Использовать новую» берёт всё из неё |

Под колонками показаны только места отличий с тремя строками контекста (остальное сворачивается), с номерами строк файла (шапка с атрибутами тоже считается) и подсветкой изменённых фрагментов внутри строк. Для каждого блока можно выбрать «Моё», «Оба» (сначала ваше, затем из Telegram) или «Из Telegram». По умолчанию выбран рекомендуемый вариант: новое из Telegram (там, где у вас в этом месте ничего нет) добавляется, а там, где правили оба, остаётся ваша версия. Переключатель «Только различия» убирает строки контекста, «Подсветка изменений внутри строк» включает и выключает выделение фрагментов.

После применения заметка считается согласованной с текущей версией Telegram: следующие импорты её не беспокоят, пока текст в Telegram снова не изменится.

### История и инфографика

Карточки: сколько заметок импортировано (и за последние 30 дней), сколько файлов и какого размера сохранено, сколько ссылок Back/Next обновлено, доля успешных сессий. Диаграмма по месяцам (заметки, файлы, пиковый месяц), кольцо типов контента (по последнему импорту каждого чата), чаты и каналы в хранилище и журнал сессий: дата, источник, объём, статус, конфликты (сколько нашлось и сколько уже разрешено), «Открыть в хранилище» и «Лог сессии». Кнопка «Экспорт отчёта в Markdown» сохраняет `Отчёт об импортах.md` в папку назначения, «Очистить кэш импорта» заставляет следующий импорт заново сравнить заметки с одинаковыми именами (история запусков остаётся).

### Папка merge_conflicts

Для каждой заметки на сравнении плагин кладёт версию из Telegram в папку `merge_conflicts` (файл `<имя> (Telegram).md`) и пишет `Отчёт о конфликтах.md`: сводную таблицу (заметка, причина, число блоков, строки у вас и в Telegram) и подробную таблицу по каждому блоку отличий с номерами строк и текстом обеих версий. Отчёт обновляется после каждого разбора. Когда конфликтов не остаётся, папка удаляется. Ваши заметки остаются нетронутыми, пока вы сами не примените выбор.

### Если в `originals/` слишком много файлов

Там должны лежать только заметки, текст которых вы правили. Если их заметно больше:

1. Проверьте, что Obsidian загрузил актуальный `main.js`: после замены файла плагин нужно выключить и включить заново (или перезапустить Obsidian). Если в папке плагина по-прежнему появляется `base/`, а не `originals/`, работает старая версия. Актуальная версия при импорте удаляет `base/`.
2. Откройте `merge_conflicts/Отчёт о конфликтах.md`: там для каждой заметки с отличиями указаны строки и текст обеих версий.

## Что важно знать

- Заметки с одинаковой датой до секунды получают одно имя файла и затирают друг друга. Это свойство формата имён, как и раньше.
- Удалённую вами заметку следующий импорт создаст заново.
- В папку назначения копируются все файлы архива, кроме `result.json` и превью-картинок (`*_thumb*`, `*_preview*`, `*.mp4.jpg`).
- Названия папок месяцев английские: `2026-09-September`.
- Системный диалог выбора папки на очень больших архивах может подвисать. Путь в текстовом поле работает всегда.

## Файлы архива: ничего не перезаписывается

Если файл уже есть в хранилище, он не копируется и не заменяется, даже если отличается размером или содержимым. Это же относится к другому формату того же файла: если у вас лежит `photo_1.webp`, то `photo_1.png` из архива не копируется. Формат считается «тем же», если файлы в одной папке имеют одинаковое имя без расширения и относятся к одному виду:

| Вид | Расширения |
|---|---|
| Изображения | jpg, jpeg, png, webp, gif, avif, heic, heif, bmp, tif, tiff |
| Видео | mp4, mov, m4v, webm, mkv, avi |
| Аудио | mp3, m4a, ogg, oga, opus, wav, flac, aac |

Кроме того, пропускается файл, у которого в той же папке уже есть копия с **идентичным содержимым** под другим именем (например, вы переименовали `photo_1.jpg`). Сравнение побайтовое, и только среди файлов одинакового размера, так что на скорости это почти не сказывается.

Документы и прочие файлы по имени сравниваются только точно (если не выбрано «Пропускать при любом расширении»): `report.docx` копируется, даже если рядом уже лежит `report.pdf`. Файлы, которые вы переместили в другую папку хранилища, плагин не ищет и скопирует заново. Заметки, созданные заново из Telegram, ссылаются на файлы под их исходными именами (например, `.png`), а не на ваши пережатые версии.

Если в настройке «Файлы с тем же именем, но другим расширением» выбрано «Копировать», всё сравнивается по точному имени с расширением: `photo_1.png` копируется, даже если рядом лежит `photo_1.webp`. Проверка на идентичное содержимое остаётся.
