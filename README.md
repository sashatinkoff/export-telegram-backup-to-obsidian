# Telegram Import

Плагин превращает архив Telegram (экспорт в JSON) в заметки Obsidian одной командой:

1. копирует файлы архива (фото, видео, документы) в хранилище;
2. из `result.json` собирает заметки с шапкой (дата, источник, теги) и разложенные по папкам `notes/год/год-месяц-Месяц`;
3. расставляет ссылки `Back` / `Next` между заметками.

Работает только на десктопе. Python не нужен.

## Установка

Положите три файла в папку `<хранилище>/.obsidian/plugins/telegram-import/`:

- `main.js`
- `manifest.json`
- `README.md` (чтобы инструкция открывалась в настройках)

Затем включите плагин в **Настройки → Сторонние плагины**.

## Как пользоваться

1. В Telegram Desktop: **Настройки → Продвинутые → Экспорт данных Telegram**, формат **JSON**, нужные чат или канал. Получится папка с `result.json`.
2. Запустите команду **«Импорт из Telegram»** (палитра команд или иконка в боковой панели).
3. В открывшемся диалоге вставьте путь к папке архива или нажмите «Выбрать…». Последний использованный путь подставляется сам, так что обычно достаточно нажать «Импортировать». Диалог можно отключить в настройках, тогда всегда берётся папка из настроек.

Прогресс виден в строке состояния, итог показывается уведомлением. Повторный импорт безопасен: при том же архиве ничего не меняется, а новый архив просто дополняет заметки.

### Команды

| Команда | Что делает |
|---|---|
| Импорт из Telegram | Полный цикл: файлы → заметки → ссылки |
| Только пересчитать ссылки Back/Next | Только третий шаг, по выбранной папке |
| Показать заметки с конфликтами слияния | Список заметок с неразрешёнными конфликтами, выбор открывает заметку |

## Настройки

| Настройка | Назначение |
|---|---|
| Папка с архивом Telegram | Где лежит `result.json`. Если включён вопрос при каждом импорте, подставляется в диалог по умолчанию и обновляется после каждого импорта |
| Спрашивать папку архива при каждом импорте | Включено по умолчанию. Перед импортом открывается диалог с путём к архиву |
| Папка назначения в хранилище | Куда попадают заметки (`notes/…`) и файлы архива. По умолчанию `Telegram`. Существующие файлы не перезаписываются |
| Папка для пересчёта ссылок | Все `.md` внутри (включая вложенные) выстраиваются в цепочку Back/Next по порядку имён. По умолчанию `Telegram/notes` |
| Пересчитывать все файлы | Включено по умолчанию. Если выключить, файлы, где уже есть Back/Next, пропускаются, и при слиянии со старыми заметками цепочка может остаться неверной |
| Беречь ручные правки | Включено по умолчанию, см. раздел ниже |
| Порог склейки, секунд | Сообщения, идущие подряд с меньшим интервалом, объединяются в один пост. `0`: не склеивать. По умолчанию 120 |
| Формат даты в шапке | Пусто: «7 сентября 2026, 09:41». Иначе строка вида `%d.%m.%Y %H:%M`. Поддерживаются `%d %m %Y %y %H %M %S %B %b` |
| Ключ Яндекс Static Maps | Нужен для превью-картинок локаций. Без ключа вместо картинки будет ссылка. Хранится в `data.json` плагина |

Папки назначения и пересчёта должны находиться внутри хранилища.

## Ручные правки и слияние

Если вы правили импортированную заметку, а потом импортируете архив снова, плагин не затирает ваши правки.

**Сравнивается только текст заметки**, то есть всё, что идёт после шапки. Атрибуты (`Date`, `tags`, `Источник`, `Back`, `Next` и ваши собственные ключи вроде `rating`) в сравнении не участвуют. Правка одних атрибутов не считается изменением заметки, а при обновлении текста существующие значения атрибутов остаются как есть. Из Telegram добавляются только новые ключи, которых у вас нет. Ссылки Back/Next всегда расставляет пересчёт. Не считаются различием и «невидимые» отличия текста: переводы строк (`\n` и `\r\n`), пробелы в конце строк, лишние пустые строки, неразрывные пробелы и символы нулевой ширины, разная форма записи одних и тех же букв в Юникоде, пустые строки цитат (одиночный `>`).

Одинаковыми считаются и ссылки на один и тот же медиафайл, записанные по-разному: `![](photo_1904@….jpg)` и `![[photo_1905@….webp]]` не отличаются. При сравнении не учитываются запись ссылки (`![]()` или `![[]]`), папка, формат файла (`jpg`, `webp`, `png`…) и сквозной номер перед `@`: он меняется при каждом новом экспорте, потому что нумеруются все файлы экспорта. Ссылки на другой файл (например, с другой датой в имени) считаются различием, как и обычные ссылки `[[…]]`.

| Ситуация | Что произойдёт |
|---|---|
| Текст совпадает | Без изменений |
| Вы правили текст, в Telegram не менялось | Остаётся ваша версия |
| Вы не правили текст, в Telegram изменилось | Текст обновляется из Telegram, ваши атрибуты сохраняются |
| Правили и вы, и в Telegram, в разных местах | Изменения объединяются автоматически |
| Правили и вы, и в Telegram, в одном месте | Конфликт: в тексте остаются оба варианта |
| Нет записи о прошлом импорте (например, удалили `import-index.json`) | Остаётся ваша версия, дальше слияние работает как обычно |

### Что плагин хранит между импортами

В папке плагина лежит немного данных:

- `import-index.json`: короткий отпечаток текста каждой заметки на момент прошлого импорта. Это один небольшой файл, сами заметки он не копирует.
- `originals/`: версия из Telegram **только для тех заметок, текст которых вы изменили** (она нужна, чтобы позже объединить ваши правки с правками в Telegram). Для заметок, совпадающих с Telegram, копий нет. Когда текст снова совпадает с Telegram, копия удаляется.

Если правка текста и изменение в Telegram произошли между двумя импортами, и плагин не успел сохранить оригинал, он не может объединить текст построчно. Тогда в заметке остаются целиком оба варианта в маркерах конфликта.

### Конфликты

Пересечение правок выглядит так:

```
<<<<<<< Мои правки (в хранилище)
ваш вариант строки
=======
вариант из Telegram
>>>>>>> Telegram (новая версия)
```

Оставьте нужный вариант, удалите три строки с маркерами и сохраните заметку. После этого она пропадёт из списка конфликтов. Пока маркеры в тексте, повторные импорты эту заметку не трогают, поэтому конфликт не дублируется.

Если выключить «Беречь ручные правки», заметка при любом отличии просто перезаписывается версией из Telegram.

### Если в `originals/` слишком много файлов

Там должны лежать только заметки, текст которых вы правили. Если их заметно больше:

1. Проверьте, что Obsidian загрузил актуальный `main.js`: после замены файла плагин нужно выключить и включить заново (или перезапустить Obsidian). Если в папке плагина по-прежнему появляется `base/`, а не `originals/`, работает старая версия. Актуальная версия при импорте удаляет `base/`.
2. После импорта откройте консоль разработчика (macOS: `Cmd+Option+I`, Windows и Linux: `Ctrl+Shift+I`; затем вкладка Console). Для заметок, где плагин нашёл отличие текста, там показана таблица: имя заметки, номер первой отличающейся строки и обе версии этой строки.

## Что важно знать

- Заметки с одинаковой датой до секунды получают одно имя файла и затирают друг друга. Это свойство формата имён, как и раньше.
- Удалённую вами заметку следующий импорт создаст заново.
- В папку назначения копируются все файлы архива, кроме `result.json` и превью-картинок (`*_thumb*`, `*_preview*`, `*.mp4.jpg`).

## Файлы архива: ничего не перезаписывается

Если файл уже есть в хранилище, он не копируется и не заменяется, даже если отличается размером или содержимым. Это же относится к другому формату того же файла: если у вас лежит `photo_1.webp`, то `photo_1.png` из архива не копируется. Формат считается «тем же», если файлы в одной папке имеют одинаковое имя без расширения и относятся к одному виду:

| Вид | Расширения |
|---|---|
| Изображения | jpg, jpeg, png, webp, gif, avif, heic, heif, bmp, tif, tiff |
| Видео | mp4, mov, m4v, webm, mkv, avi |
| Аудио | mp3, m4a, ogg, oga, opus, wav, flac, aac |

Кроме того, пропускается файл, у которого в той же папке уже есть копия с **идентичным содержимым** под другим именем (например, вы переименовали `photo_1.jpg`). Сравнение побайтовое, и только среди файлов одинакового размера, так что на скорости это почти не сказывается.

Документы и прочие файлы по имени сравниваются только точно: `report.docx` копируется, даже если рядом уже лежит `report.pdf`. Файлы, которые вы переместили в другую папку хранилища, плагин не ищет и скопирует заново. Заметки, созданные заново из Telegram, ссылаются на файлы под их исходными именами (например, `.png`), а не на ваши пережатые версии.
- Названия папок месяцев английские: `2026-09-September`.
- Выбор папки кнопкой «Выбрать…» на очень больших архивах может подвисать. Путь в текстовом поле работает всегда.
